# Research Alignment

The lab translates Android forensic research into operational modules.

## Literature Review and Tool Efficacy

Kumar, Narayan, and Rasid identify Android acquisition methods, tool coverage limitations, encrypted data constraints, anti-forensic tactics, cloud evidence complications, and admissibility concerns. The platform reflects this through the method comparison engine, tool coverage matrix, evidence feature model, and limitations reporting controls.

## Stealth-Attack Detection and Memory Forensics

Sanna's doctoral research focuses on Android stealth attacks, native code vulnerabilities, memory acquisition, anti-analysis behavior, and intelligent detection approaches. The platform maps those themes to native-code risk review, memory capture planning, anti-analysis checks, static malware review, dynamic malware review, and expert-review controls.

## Comparative Method Analysis

Gunay, Gul, and Ertam compare manual, logical, and physical Android forensic methods across nine evidence features. The method engine uses this structure to make method-selection reasoning explicit and to show where physical imaging, logical extraction, manual review, cloud acquisition, memory acquisition, or application analysis should be used as primary or supporting methods.

## File-Wiping Evaluation

Oh and colleagues evaluate Android file-wiping applications through static analysis, dynamic analysis, artifact analysis, standards alignment, recoverability, and residual traces. The wiping module follows the same practical questions: what did the app claim, what behavior was observed, was content recoverable, did residual artifacts remain, and how should findings be expressed defensibly.

## Practical Lab Operations

Bhardwaj and Kaushik provide broad practical guidance for lab setup, evidence handling, and structured investigation. The platform applies those operational themes to chain of custody, device isolation, photographic record, hash manifests, peer review, reproducible appendices, audit retention, and structured reporting.

## Design Principle

No single Android forensic method or tool is treated as complete. The platform encourages layered acquisition, independent validation, transparent limitations, and clear confidence labeling.
